# Canonical Strict Injector Coverage Audit — 2026-08-07

This is the single reproducible union audit that replaces the disagreeing
`batch0053` and live audits. It is generated by one checked-in command:

```
PYTHONPATH=src python3 src/gen/fuzzlang_dsl/run_canonical_strict_audit.py \
  --audit-out data/gen/experiments/clang-test-gap-injector-v0002/canonical-strict-injector-audit-20260807.json \
  --report-dir data/reports/strict-injector-coverage-20260807-canonical
```

The input list is the pinned batch-6 base audit plus the explicitly enumerated
post-batch-6 campaigns in `POST_BASE_CAMPAIGNS` (no globbing of live
directories). `input_manifest.csv` records the SHA-256, byte size, and row
count of all 1,971 input files, so the audit can be recomputed and compared
byte for byte. All generation jobs were stopped before this audit ran, so the
inputs are final.

## Admission gate

A diagnostic type counts only when a Record satisfies every gate in
`gen/fuzzlang_dsl/coverage_audit.py`:

- clean, non-test, non-test-support parent translation unit;
- `corrected_src` present and different from the erroneous source;
- the compiler's primary typed diagnostic exactly equals the record's target
  (name and, where the Injector pins it, `DiagID`);
- a portable FuzzLang Injector exists, and for witness-replay strategies the
  Injector recorded in provenance is the one that must match;
- the target is an error diagnostic in the pinned `llvmorg-22.1.8` catalog.

Candidates, unreplayed Injectors, incomplete campaigns, and Clang
regression-test sources are therefore never in the numerator. Clang test text
remains prompt-only evidence.

## Two numerators from identical inputs

| rule | paper-scope types | batch-6 baseline | new vs batch 6 | strict records |
|---|---:|---:|---:|---:|
| **strict (headline)** | **1,195 / 1,935** | 981 | **+214** | 6,850 |
| inclusive | 1,242 / 1,935 | 1,029 | +213 | 7,535 |

The two rules differ only in whether a record with
`opportunistic_observed_diagnostic = true` counts. Such a record is a verified
clean-parent/failing-mutant pair, but its `target_diag` was *relabelled* to
whichever catalog error the mutation happened to emit, so it is not evidence
that the requested gap was reached. The **strict** rule drops those 685 records
and is the headline; the inclusive rule is published only so the difference is
visible instead of silently chosen. Both baselines are recomputed from the same
batch-6 inputs under the same rule, so a strict numerator is never compared
against an inclusive baseline.

47 paper-scope diagnostic types are backed *only* by opportunistically
relabelled records; `uncovered_paper_scope_gaps.csv` marks them with
`covered_only_by_opportunistic_record=true`.

## Difference versus `batch0053` and the live audit

All three audits use the same gate and the same batch-6 base. They differ only
in which completed campaign files each one enumerated:

| audit | rule | paper scope | new vs batch 6 | record files |
|---|---|---:|---:|---:|
| `strict-injector-coverage-audit-batch0053-direct-fixed.json` | inclusive | 1,200 / 1,935 | +171 | 1,346 unique (1,623 listed, 277 duplicated) |
| live `build_batch0074_final_audit.py` output | inclusive | 1,241 / 1,935 | +212 | 1,344 |
| **this canonical audit** | inclusive | 1,242 / 1,935 | +213 | 1,348 |
| **this canonical audit** | **strict** | **1,195 / 1,935** | **+214** | 1,348 |

- **batch0053 → live (+41 types).** The live audit added two completed campaign
  record files that batch0053 never read: the B62 C++23 emission-tail witness
  run and the B63 Abseil C++23 witness run.
- **live → canonical (+1 type).** The live audit *dropped* four witness record
  files that batch0053 had included (B33, B34, B36, B49 `gemma-run`), counting
  only their `replay` output. One record in those files
  (`err_init_capture_paren_braces`) had been rejected in the live audit as
  `recorded_injector_missing_or_mismatched`; with both files present its
  Injector resolves and it is admitted. The canonical audit therefore includes
  *both* the witness and the replay file of every campaign that produced both.
- batch0053 also listed 277 record files twice. Duplicate paths are deduplicated
  here and reported in `duplicate_input_paths`.

No campaign was added on the basis of running or partially replayed output.
B62 and B63 were cancelled mid-campaign; the records they had already written
each passed the full gate independently, and no further output can be produced
because all jobs are stopped. Campaigns declared but never completed (B66, B68,
B69, B70, B72, B73, B75, B77, B79, B81, B83, B85, B87) produced no
`records.jsonl` and are skipped, not partially counted.

## Files

- `summary.csv` — headline counts under both rules.
- `diagnostic_record_map.csv` — the release manifest mapping: one row per
  covered diagnostic with its component, strict record count, distinct source
  translation units, projects, generation strategies, campaign count, and the
  Injector IDs responsible.
- `input_manifest.csv` — every audited input file with SHA-256, size, and rows.
- `uncovered_paper_scope_gaps.csv` — the 740 paper-scope diagnostics with no
  strictly verified record, flagged where only an opportunistic record exists.

These CSVs contain metadata only: no program source, test source, Injector
payload, or training record.
